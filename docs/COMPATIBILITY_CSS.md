# CSS Compatibility

Pages use standard CSS, drawn by `@pierre/apps` on the GPU. Transforms, filters, blend modes, masks and clip paths paint through offscreen GPU layers.
These parts differ from browsers. The ones that don't work show an error in the Developer Tools console (`apps run -D`): properties and at-rules that `@pierre/apps` reads but does not apply, like `text-emphasis` and `@counter-style`, and values it rejects. `@supports` and `CSS.supports()` return false for them. As in browsers, a rejected value is dropped, so an earlier value of the property applies.

| Feature | Support |
|---|---|
| `transform-style: preserve-3d` | Planes that go through each other split only where the cut is vertical or horizontal in one of them, and not when one has a filter, a blend mode or a backdrop, or an animation in the context is composited. Others draw whole, by the depth of their centers, as do all planes of a context with more than 512 of them. `::before` and `::after` stay in the plane of their box. Where planes go through each other, the one drawn last takes the pointer. The scroll range counts each 3D transform flattened. Animations of planes redraw the page on each frame: the compositor doesn't run them |
| `filter: url()` | Only `<filter>` elements in the page, with `feGaussianBlur`, `feColorMatrix` and `feDropShadow`. An `feOffset` works only together with an `feGaussianBlur`, as a drop shadow |
| `mask` | `mask: url(#id)` with an SVG `<mask>` draws nothing, `-webkit-mask-clip: text` and `-webkit-mask-composite: plus-lighter` are rejected, and the `mask` and `offset` shorthands in a `style` attribute don't list their longhands |
| `offset-path` | `::before` and `::after` take only `path()`: the other shapes and `url()` don't move them. Inline boxes and SVG elements are not moved by shapes other than `path()`. An `offset-path` or `offset-distance` animation draws a page frame for each step |
| `zoom` | Not supported |
| Image functions | `-webkit-cross-fade()` works in `background-image` only, and each of its images has its own size, not the blended one. An `image-set()` in `border-image` ignores the resolution of its image. `paint()` is not supported. The old gradients `-webkit-gradient()`, `-webkit-linear-gradient()`, `-webkit-radial-gradient()` and their repeating forms parse but draw nothing |
| `background-clip: text` | The background shows through the text of the box and of its children, and through their text decorations. The text of a child with its own `opacity`, transform or filter doesn't let it through. A list that mixes `text` with other boxes clips all layers to the text. On `html` and `body` it is ignored |
| `border-image` | Inline boxes place the image around their line height, not the content area of their font, and a box that spans several lines gets one image. A file that can't be decoded draws no border. `border` resets only the source, so the other `border-image` longhands keep their values |
| `background-attachment: fixed` | Works on the background of the page (`html`, or `body` when `html` has none). On other elements the layer scrolls with its box |
| `vector-effect: non-scaling-stroke` | Undoes the `viewBox` scale of the `<svg>`, but not transforms inside it |
| `line-height`, `vertical-align` in `::first-letter` and `::first-line` | Ignored. Sizes, colors and font styles work. A `::first-letter` with `float` stays in its line, so drop caps don't work |
| `::before`, `::after` | Their `clip-path` shapes and `outline` are not drawn, their background stays inside their border, and a floated one in a box that holds only inline content goes to its side of the first line, where text doesn't flow around it. An inline one with a background, border, padding, margin or effect stays whole on one line, like an inline-block. `content` draws only text: strings, `attr()`, counters and quotes. Its images and gradients are not drawn. With `quotes: auto`, quotes are English ones in all languages |
| Other pseudo-elements | `::details-content`, `::target-text`, `::spelling-error`, `::grammar-error`, `::search-text`, `::checkmark`, `::picker()`, `::picker-icon`, `::cue`, `::column`, `::scroll-marker`, `::scroll-marker-group`, `::scroll-button()` and the `::view-transition` ones parse, but their rules have no effect |
| `attr()` | Works only in `content`. In other properties, a value with `attr()` has no effect |
| Wide-gamut colors | As in Chrome, a window on a wide-gamut Mac screen draws in Display P3, so colors like `oklch()`, `lab()` and `color(display-p3 …)` keep their saturation. Colors outside sRGB still clip to sRGB in SVG, scroll bars, form controls, `accent-color`, `caret-color`, `::selection`, `flood-color` and terminals, and on Windows and Linux everywhere. `capturePage()` and developer tools screenshots return sRGB pixels, where Chrome returns the pixels of the screen. The `APPS_FORCE_COLOR_PROFILE` environment variable is `srgb` or `display-p3`, like Chrome's `--force-color-profile`, and with `display-p3` captures return Display P3 pixels |
| Default font | Pages without a `font-family` use the system font, where browsers use Times. `ui-serif`, `ui-sans-serif`, `ui-monospace` and `ui-rounded` are skipped, so the next family of the list applies, or else the system font |
| Text decoration | `text-decoration-skip-ink` takes `auto` and `none`, and `text-underline-position` doesn't take `from-font`. A nested inline box uses its own underline position and offset, where Chrome uses those of the box with the decoration. Like other layers, a transformed box scales its lines after they are placed |
| `-webkit-text-stroke` | Works, with the stroke over the fill. On Windows text draws without its stroke. Neighbor glyphs stroke separately, so a translucent stroke is darker where they overlap. A `::selection` style draws the selected text without a stroke, and its own stroke properties are ignored |
| Custom highlights | `::highlight()` draws colors and text decorations, not `text-shadow`, and its rules inside `@container` and after `:host` or `::part()` don't apply |
| `outline-style: auto` | Draws Chrome's focus ring. `-webkit-focus-ring-color` is `#005fcc`, or `#99c8ff` in a dark `color-scheme`, not the system accent color |
| `content-visibility` | `hidden` and `auto` skip the contents of block, inline-block, flex, grid and flow-root boxes: they are not built, laid out, painted, hit or in `innerText`, and the box sizes as if empty, or as its `contain-intrinsic-size`. `<table>` elements show their contents. `auto` shows the contents while the box is within 150% of the window size from the view, or has the focus or the selection in it, as in Chrome, and its skipped contents can take the focus. `contain-intrinsic-size: auto` remembers the last size the box had with its contents. Styles of skipped contents are still computed. A script that reads the geometry of a node in skipped contents gets a layout of them inside the box, which keeps its skipped size. The order of `contentvisibilityautostatechange` events in one frame can differ from Chrome. `hidden=until-found` uses `content-visibility: hidden`, and fragment navigation reveals it after `beforematch`, but find-in-page doesn't exist |
| Size containment | `contain: size`, `inline-size` and `strict`, and `container-type: size` and `inline-size`, don't size the box as if it were empty: it takes the size of its contents, where Chrome gives it 0 or its `contain-intrinsic-size`. `container-type: scroll-state` and `anchored` are not supported |
| `font-variant` | `font-variant-alternates` takes only `historical-forms`, and `font-variant-emoji` is not supported. As in Chrome, small caps use the features of the font, or else capitals at 70% of the size. A letter whose capital is more letters, like `ß`, stays small as it is |
| `font-size-adjust` | Takes a number, `cap-height` and `ch-width`, but not `from-font`, `ic-width` and `ic-height`. Fallback fonts are not adjusted |
| `hyphens` | `auto` hyphenates with the dictionaries of macOS, which differ from Chrome's in some words, and is like `manual` on Windows and Linux. A row with `overflow-wrap: anywhere` can end at another letter before a hyphen, and `text-wrap: balance` can choose other hyphens. `hyphenate-limit-chars` is not supported, and text fields show no hyphens |
| Variable fonts | `font-variation-settings` and `font-optical-sizing` work on macOS and Linux. As in Chrome, `font-optical-sizing: auto` sets the `opsz` axis of web fonts to the font size in CSS pixels, and macOS sizes its system fonts itself. On Linux, axes other than `wght` change the glyphs but not their advances. On Windows, both properties are ignored |
| Line breaks | Lines break by the line break classes of Unicode, with Chrome's rules for pairs of ASCII characters. Thai, Lao, Khmer and Myanmar text has no dictionary, so it can break between any two letters. In `pre-wrap` text, lines break before their tabs are placed, so a break can be off |
| Font fallback | On macOS, a character that the font lacks comes from the next installed families of `font-family`, then from the system fonts. On Windows and Linux, only the first installed family applies. A generic family like `serif` is one font, so text in other scripts, like Arabic, can get another font than in Chrome |
| `text-transform` | `uppercase` and `lowercase` use the full case mappings, like `ß` to `SS`, except in `::first-letter`, `::first-line` and form fields, where a letter that maps to more letters stays as it is |
| Synthetic bold and italic | On macOS, as in Chrome, a face without the asked bold (600 or more) or italic draws its glyphs emboldened or slanted. A glyph from a fallback font doesn't get them. Windows and Linux draw the face as it is |
| `float` | Lines beside a float are shorter and go on under it, and a float reaches the blocks after it and the blocks inside them. A float in the middle of a paragraph goes to the top of the paragraph, not to its line. A line of inline-blocks or other boxes moves beside a float as a whole, where browsers make each line shorter. In a paragraph with lines of different heights, the lines can end beside a float one line early or late. `shape-outside` takes basic shapes and boxes, but not `path()`, `shape()` and images, and a line of text that stands between blocks runs beside the margin box of the float. A `<br>` with `clear` works between lines of text |
| Inline content in text | Inline boxes split across lines, and inline-blocks, images and controls sit in the line. A paragraph with an absolute or fixed box that has an `auto` inset on both sides of one axis and a box in a layer of its own after it, and an inline box with a transform or animation, or with opacity and a box shadow, text shadow or outline, wrap as separate pieces, so they break before and after such a box. So do the lines of an inline box with such a child of its own. As in Chrome, other absolute and fixed boxes leave the lines of a block as they are, also inside its inline boxes and as their `::before` and `::after`. An absolute box that was inline, `::after` too, takes its static place in its line, and a positioned inline box contains the boxes in it from the start of its first line to the end of its last. Text next to a new inline-block can move for one frame, until its size is known. `getClientRects()` of an inline box returns one rectangle, however many lines it spans. Percentages in the padding and margins of an inline box count as 0. `text-align: justify` doesn't stretch the spaces between inline-blocks in a line that has only boxes. An inline box draws its outline on each line, and `groove`, `ridge`, `inset` and `outset` outlines there draw as `solid`. An inline box that wraps as separate pieces draws one outline around all its lines |
| Blocks in inline boxes | As in CSS 2.1, an inline box that holds a block splits around it: the text before and after the block joins the lines of the block around it, and `getClientRects()` gives one rectangle for each part. The box has no box of its own, so its `opacity` applies to each piece on its own (the background, the borders, the text and each block and inline-block), so where they overlap they blend unlike Chrome's one group. Its filters and relative offset are not drawn, and its outline goes only around its parts in the lines. An inline box with an inline or out-of-flow `::before` or `::after` becomes a block instead. In a nested inline box, `getClientRects()` of the outer box doesn't split its parts at the inner box. On a right-to-left line, the open sides of the parts are on the wrong side |
| Multi-column layout | Columns balance and break as in Chrome: text breaks between its lines and follows `orphans` and `widows`, a box breaks with its border cut at the break, `break-before`, `break-after` and `break-inside` work, and `column-fill: auto` with a height fills the columns in order. Flex rows, grids, tables, inline-blocks, text with lines of different heights, boxes with a gradient or image background, an outline, a positioned child, a transform or opacity, and multi-column boxes inside columns don't break: each stays whole in one column. `box-decoration-break: clone` is not supported, and the `cursor` of a box that columns split applies only over its first part. Boxes in columns are always built, also far outside the window, so very long content in columns is slower |
| Tables | Table parts outside a table get an anonymous table only when all the children of their block or inline-block parent are table parts. Text or blocks between the cells, an inline parent, and cells inside a cell keep such cells stacked as blocks. `border-collapse` applies to `<table>` elements only. A collapsed border of a cell that spans rows or columns looks the same along its side, as its widest part. `getBoundingClientRect()` of a `<col>` is empty. |
| Vertical writing modes | A box with vertical lines in a box with horizontal lines lays out in a turned frame. The sides and sizes of the blocks in it turn with the frame, so their `margin-left` is above them. All glyphs turn, also CJK ones that Chrome keeps upright, and `text-orientation` is ignored. Images and form controls inside turn too. `getBoundingClientRect()` of inline boxes in it is not turned. In `vertical-lr`, unequal margins between blocks swap. A flex item with vertical lines stretches only in a container of a definite height |
| Tailwind CSS v4 | `@import "tailwindcss"` compiles the classes in the page when they appear, as Tailwind 4.3 does, with its import options and directives. These parts differ: `@plugin` and `@config` are not supported. `source()` and `@source` paths have no effect, because classes come from the page, so a class that no element has makes no rule. All variables of `@theme` blocks are in `:root`, also the ones that no CSS uses. `@reference` reads no file: it uses the theme, utilities and variants of the other stylesheets in the page. A mistake, like an unknown class in `@apply` or a `@utility` that applies itself, is skipped, where Tailwind reports an error. `@apply` of a mixin and `@scope` in variants are not supported |
| Liquid Glass | Needs macOS 26, and its press feedback macOS 27. Only boxes with uniform corners, no transforms or filters, and no clipping or other content above them get glass. Other boxes, and all boxes on other platforms, keep their CSS look. `bg-glass-interactive` doesn't turn glass on by itself, and only the tint utilities work with variants and `@apply`. `capturePage()` rejects frames with glass, and `<iframe>`, `<webview>` and `WebContentsView` show above it |
| `appearance: system` | On macOS, inputs with `appearance: system` (the Tailwind class `appearance-system`) show AppKit controls: `button`, `submit` and `reset` show `NSButton`, `checkbox` with the `switch` attribute `NSSwitch`, `range` `NSSlider`, `number` `NSStepper`, `text`, `email`, `url` and `tel` `NSTextField`, `search` `NSSearchField`, `color` `NSColorWell` and `date` `NSDatePicker`. Other inputs and other platforms use `auto`. Like web views, the controls draw above the page: CSS sets their size and place, and ancestors with `overflow` clip them, but padding, borders, backgrounds, other styles, transforms and boxes painted over them don't apply. They are light unless their `color-scheme` allows dark, and with both they follow the window. Presses arrive as `click`, and edits as `input` and `change`. The page can't focus them, so `focus()` doesn't move the keyboard to a native field |
| Overscroll | A trackpad bounces any box that scrolls at its edges, like Safari, with AppKit's curve. Boxes and pages with nothing to scroll and mouse wheels don't bounce. `scrollTop` and scroll events stay in range during a bounce. `overscroll-behavior` on the root element applies to the page, not on the body. `contain` and `none` also stop scrolling at boxes with `overflow: hidden` or nothing to scroll, as in Chromium |
| Scroll snap | Works as in Chrome, also in shadow trees, but an offset that a script reads before the first layout of a box is not snapped. `block proximity` keeps `proximity` when scripts read it. `scrollsnapchange` and `scrollsnapchanging` fire as in Chrome, and a mouse wheel scroll that ends at a snap position fires `scrollsnapchanging` too, as the standard says |
| `caret-shape`, `caret-animation` | Work as in Chrome, but a `bar` caret is as tall as the line, not the font. As in Chrome, there is no `caret` shorthand. `<terminal>` ignores both |
| Scroll anchoring | As in Chrome, a scrolled page or scroll container keeps the first box it shows in place when content above it changes size, and `overflow-anchor: none` turns this off. The offset moves only on the vertical axis, so vertical writing modes have no anchoring. A focused field is not preferred as the anchor, and a scroll container inside is an anchor as a whole: the boxes in it are not |
| Scrollbars | Drawn as macOS overlay bars on all platforms. They show while the box scrolls or the pointer is on them, then fade out, and they take no space. The knob is light on a dark `color-scheme` or background. The macOS "Always" scroll bar setting is ignored. `scrollbar-width` and `scrollbar-color` work |
| `::-webkit-scrollbar` | Gives bars that always show and take space, as in Chromium. `-track`, `-thumb`, `-thumb:hover` and `-corner` use the background color, border, `border-radius` and `background-clip`. Buttons, other scrollbar states and background images are not drawn. `scrollbar-gutter: stable` works only with these bars |
| `app-region`, `-webkit-app-region` | `drag` and `no-drag` work as in Electron. The value is inherited, so `getComputedStyle()` returns it for children, and a box that only overlaps a drag area doesn't move the window |
| `cursor` | Images (`url()`, `image-set()`) are not supported, and a value with an image works as `auto`, without its fallback keyword. `help`, `wait`, `progress`, `cell`, `zoom-in` and `zoom-out` also work as `auto` |
| `resize` | The user can't resize boxes. A `<textarea>` shows the grip, but a drag on it does nothing |
| Other layout properties | `reading-flow`, `reading-order`, `interactivity`, `scroll-initial-target`, `scroll-marker-group`, `column-height`, `column-wrap`, `row-rule` and `touch-action` are not supported |
| `@font-face` | `url()` takes files of the app and `data:` URLs in base64. `local()` matches installed family names, not full or PostScript names. A face with `unicode-range` loads when the page text uses one of its characters. The `font-display` and the metric override descriptors are ignored. On Windows, synthetic bold and slant are not drawn, and faces with the same family name in their files can't be told apart by `unicode-range`. Faces load before the page first draws or when `document.fonts` is read. Color fonts draw in one color, so sources with a color `tech()` are skipped |
| `border-radius` | Percentages in the corners of `<img>` content use the box's `width` and `height` properties, so they are off on images that are sized by their content |
| SVG files in `<img>` | The image fills the content box: `object-fit` and `object-position` are ignored, and `border-radius` doesn't clip it |
| `corner-shape` | Dashes and dots of a border keep the spacing of a round corner. Concave corners don't shrink the radii when opposite corners overlap, and their inner border edge, spread shadows and blurred `notch` shadows are close to Chrome but not exact. `corner-shape` doesn't animate, and the `corner-block-*-shape` and `corner-inline-*-shape` shorthands are not supported |
| `aspect-ratio` | Applies to the border box of boxes other than grids, so such a box with `box-sizing: content-box` and padding or borders gets another height |
| Anchor positioning | Works as in Chrome. `::before` and `::after` can be neither anchors nor boxes with an anchor. Keyframes, `animate()` and transitions don't take anchor functions, `anchor-name` or the `position-` properties, and the insets, sizes and margins that anchors give a box don't transition, also to or from other values. An absolute box in a grid takes the grid, not its grid area, for its anchors, and without an anchor `anchor-center` is not `center` at the static place. An anchor that wraps in its line counts as one rectangle of the place that layout gives it. An anchor that is rotated, or in a containing block that is rotated, counts as its bounding rectangle. A composited transform animation of an anchor moves the box only in frames that draw the page. An animation that makes an ancestor a containing block, or changes the visibility of an anchor or a font size that anchor functions use, doesn't count. Names of anchors and `@position-try` rules belong to the tree of their element, also when `:host` or `::part()` rules of another tree set them. A chain of more than about 60 boxes that are anchored to each other settles over several frames. `getComputedStyle()` keeps `safe` and `unsafe` before `anchor-center` |
| `calc-size()` | Not supported in `flex-basis`. In `max-width` and `max-height`, its basis can't be `auto`. On a replaced element, a grid item, and in `min-width` and `max-width`, the content size is an estimate. With `auto`, flex items, `justify-self` grid items and absolute boxes don't take the size that `auto` stretches or shrinks them to, `content-visibility` boxes take the size of their contents, and an `<iframe>` its default size |
| `direction: rtl` | Logical properties, text alignment, floats, flex rows, grid columns and block boxes follow the direction. Text that mixes directions is reordered as in Chrome |
| `@scope` | `@scope` without a selector applies to the whole page, not to the parent of its `<style>`. Scope proximity doesn't affect the cascade |
| Media queries | `device-width`, `device-height`, `device-aspect-ratio`, `overflow-block`, `overflow-inline` and `grid` never match |
| `:host-context()` | Not supported, like in Safari |
| Container style queries | `@container style(--name: value)` and `style(--name)` test the custom properties of the parent element, and for `::before` and `::after` of their own element. A named query tests the nearest ancestor with that `container-name`. Style queries of standard properties never match, as in Chrome |
| `-webkit-` properties | The `-webkit-` names of most standard properties work as in Chrome. `-webkit-writing-mode`, `-webkit-shape-outside`, `-webkit-shape-margin`, `-webkit-box-decoration-break`, `-webkit-font-feature-settings`, `-webkit-border-image` and `-webkit-opacity` are not supported, and neither are the logical names like `-webkit-margin-start` and the old flexbox properties like `-webkit-box-pack`. `-webkit-backdrop-filter` stays a property of its own, so Safari styles keep their blur |
| Text, font and paint properties | Not supported: `text-emphasis`, `text-combine-upright`, `text-justify`, `text-spacing-trim`, `text-autospace`, `initial-letter`, `line-break`, `font-palette`, `font-language-override`, `image-orientation`, `object-view-box`, `dynamic-range-limit`, `-webkit-box-reflect`, `-webkit-text-security`, the SVG properties `dominant-baseline`, `alignment-baseline`, `baseline-shift`, `marker` and `d`, and the at-rules `@font-palette-values` and `@font-feature-values`. The longhands `white-space-collapse`, `text-wrap-mode`, `text-wrap-style` and `font-synthesis-*` are rejected, but `white-space` with its single keywords, `text-wrap` and `font-synthesis` work. The values `background-clip: border-area`, `word-break: auto-phrase`, `text-decoration-line: spelling-error` and `grammar-error`, percentages in `word-spacing`, strings in `text-overflow` and the color `-webkit-link` are rejected |
| Ruby | `<ruby>` lays out as inline text, so `<rt>` text stays in the line after its base, and `ruby-position` and `ruby-align` are not supported |
| Counters | `@counter-style` and `symbols()` are not supported. Of the predefined styles, only `decimal`, `decimal-leading-zero`, the Latin, Roman, Greek, Armenian, Georgian and Hebrew ones, `hiragana`, `katakana`, `cjk-decimal`, `cjk-ideographic`, the informal Chinese ones, `disc`, `circle`, `square` and the disclosure ones work. Others, like `arabic-indic`, `thai` and `japanese-formal`, count in `decimal` |
| Lists | `list-style-image` takes only `none`, so markers are never images. An `inside` marker stays at the start edge of centered or right-aligned text, and before an inline box next to blocks it overlaps the text |
| `<legend>` | In a `<fieldset>` with rounded corners, the legend is drawn inside the border instead of on it |
| Registered custom properties | `@property` values compute to their canonical form, like `rgb()` for colors. Relative lengths like `2em` compute when scripts read them, so an inherited `2em` resolves with the font size of the element that uses it. `light-dark()`, system colors, images and URLs keep their written form |
| Transform animations | Lists that don't match function by function interpolate as matrices only when their lengths are in `px` and they have no `perspective()`. Other such lists switch halfway |
| Other animated values | `font-style` from `normal` to an `oblique` angle switches halfway, where Chrome interpolates it |
| Scroll-driven animations | Not supported: `animation-timeline`, `animation-range`, `scroll-timeline`, `view-timeline` and `timeline-scope` are rejected |
| Animations and `!important` | CSS and script animations of pseudo-elements override `!important` declarations, where browsers keep the important value |
| Animations out of view | Animations and transitions that only paint and can't move the box (rotate, scale, opacity, colors, shadows) pause while the box is outside the window or clipped away. They go on at the current time when the box comes into view, and fire no `animationiteration` events meanwhile |
| Animation frame rate | A smooth keyframe value draws again only when it moves by a visible step: a quarter pixel, a tenth of a degree, and 1% of opacity or a color level, up to 4 times more on boxes under 48px. So a slow animation can draw fewer frames than the display, and `getComputedStyle()` can return the value of its last drawn frame |
| Composited animations | Animations and transitions of `opacity`, transforms, and `filter` and `backdrop-filter` with one `blur()` at both ends, and `opacity` animations of `::before` and `::after`, draw without laying out the page. On macOS Core Animation runs them while nothing on the page draws above the box and nothing blurs, and otherwise each frame draws the region of the box again. `IntersectionObserver` sees such a box where the last full frame drew it. As in Chromium, `animationiteration` doesn't wake a page that never listened for it |
| `var()` fallbacks | Fallbacks nested more than 32 levels deep make the value invalid |
| Value functions | `sibling-index()`, `sibling-count()`, `if()`, `random()`, `progress()` and functions of `@function` are not supported |
| Huge text | A glyph bigger than 2048 device pixels on a side draws from a smaller raster, so its edges are soft. On Windows so does text with a font size over 800 device pixels |
| `getComputedStyle()` | `grid-template-columns` and `grid-template-rows` of a grid give its used tracks, but the `grid-template` and `grid` shorthands keep the computed values. `background-image`, `mask-image`, `border-image-source`, `cursor`, `filter`, `backdrop-filter` and `scrollbar-color` keep their URLs and colors as written. `text-decoration-line` includes the lines a box gets from its ancestors. An explicit `overflow: visible` on a `<textarea>` stays `visible`, though the textarea scrolls like `auto` |
| CSSOM | `@import` works only in bundled CSS, so `CSSImportRule.styleSheet` is `null`. In `cssRules`, an `@scope` rule is a `CSSStyleRule` with a `:where()` selector, an `@starting-style` rule is a plain `CSSRule` with no text, and declarations after a nested rule have no `CSSNestedDeclarations`. A keyframe rule with several selectors, like `0%, 50%`, is one rule for each. The `style` attribute keeps its text as written, where browsers rewrite it: `cssText` and property reads give the browser form |
