# Node.js Compatibility

The main process, preload scripts and their workers can import these built-in modules, with or without the `node:` prefix: `assert`, `async_hooks`, `buffer`, `child_process`, `crypto`, `diagnostics_channel`, `dns`, `events`, `fs`, `http`, `https`, `module`, `net`, `os`, `path`, `perf_hooks`, `process`, `querystring`, `readline`, `stream`, `string_decoder`, `timers`, `tls`, `tty`, `url`, `util`, `v8`, `worker_threads` and `zlib`. `undici`, `ws` and `node-pty` are also built in for the main process. Imports of these names never load a package from `node_modules`. Their `/promises`, `/strict`, `/posix`, `/win32`, `/types`, `/consumers` and `/web` subpaths also work. `node:sqlite`, `node:ffi` and `node:sea` are available too.

`@pierre/apps` follows the Node.js 24 API, so `process.version` is `v24.0.0`. Deprecated and experimental APIs, like `url.parse()` and `fs.exists()`, are not included. These parts differ from Node.js:

| Feature | Support |
|---|---|
| Other modules | `cluster`, `dgram`, `domain`, `http2`, `inspector`, `punycode`, `repl`, `test`, `trace_events`, `vm` and `wasi` are not supported. Importing them fails at build time. A `require()` of them, or of any module that can't be found, throws `MODULE_NOT_FOUND` when it runs. `constants` and `sys` work, but `constants` has no named imports |
| `ns.fn()` | In built apps, a function called through `import * as ns` gets `this` as `undefined`, like other bundlers, where the standard says `ns`. `apps run` follows the standard |
| Import attributes | `with { type: 'text' }` imports a file as a string. For an HTML file in the main process, the string is the bundled page. A `.json` file is a JSON module with or without `type: 'json'`. Other types are ignored. `import()` takes its type only from an object literal, like `{ with: { type: 'text' } }` |
| `require()` | App code is ESM. CommonJS works in `node_modules`, with `module`, `__filename` and `__dirname`. `require()` with a computed name loads built-in modules only. A function from `module.createRequire()` works like `require()` when it is kept in a variable, and else loads built-in modules only. `module` has only `builtinModules`, `isBuiltin()` and `createRequire()`. `require.resolve()` finds string literals only. `require.main` is `undefined`, because the entry is ESM. `require()` uses the package `main`; `import` uses `main`, then `module` |
| `import.meta.url`, `__filename` | In built apps they point into the app: `import.meta.url` is `apps:///` plus the path in the app, and `__filename` is that path in the app folder. `url.fileURLToPath()` turns the URL into the same path. `import.meta.filename` and `import.meta.dirname` work in main, preload scripts and workers; pages get `undefined`. Files outside the app folder, like packages in a parent `node_modules`, keep their path relative to it, like `apps:///../shared/x.js` |
| Partial modules | `AsyncLocalStorage` keeps its store only in the synchronous part of `run()` and in functions from `bind()` and `snapshot()`, not across `await`. `tls` has client sockets only: `tls.createServer()` and client certificates (`cert`, `key`, `pfx`) throw. `tls.connect()` also takes a connected `socket`, for STARTTLS. `ca` replaces the system roots for the connection, as in Node. `checkServerIdentity`, `minVersion`, `maxVersion`, `ciphers` and sessions are not supported, `getPeerCertificate()` returns only `raw`, and `rootCertificates` and `getCACertificates()` are empty. `v8` reports process memory as heap statistics, its `serialize()` uses JSON, and it has no heap snapshots, `Serializer` or other statistics. `node:sea` reports that the app is not a single executable: `isSea()` is `false` and there are no assets |
| `undici`, `ws`, `node-pty` | `undici` has `fetch()`, `request()`, `Agent`, `Client`, `Pool` and the global dispatcher, which all use `fetch`. `dispatch()`, `stream()`, `pipeline()`, `connect()`, `ProxyAgent`, `MockAgent` and connection options don't work. `ws` wraps the global `WebSocket`: a client can't set headers or options, and has no `ping()` or `pong()`. A `WebSocketServer` takes connections only from the `upgrade` event of an HTTP server, with the `server` option or `handleUpgrade()`, so the `port` option doesn't listen. `node-pty` has `spawn()` with `pid`, `cols`, `rows`, `write()`, `resize()`, `kill()`, `onData()` and `onExit()`. There is no `pause()`, `resume()` or `clear()`, and `process` is the spawned file |
| `ELECTRON_RUN_AS_NODE` | With this variable the executable runs a script headless, with no windows, and it can run a script chunk from `import.meta.resolve('./file.ts')`. With `NODE_CHANNEL_FD` it talks to its parent like a forked Node.js process. Options before the script, like `--require`, are ignored |
| `process` | `memoryUsage()` returns `rss` only, the heap values are 0. An unhandled promise rejection is logged and does not stop the app. An error given to `reportError()` fires `error` on `globalThis` and then goes to `uncaughtException`, or to the console. `process.kill()` doesn't work on Windows. A built app gets all of its arguments in `process.argv` after the executable, like Electron, so there is no script path. `process.exit()` throws in preload scripts. `process.chdir()` throws `ERR_WORKER_UNSUPPORTED_OPERATION` in preload scripts too, as in workers, because they are threads of the app process. `nextTick()` callbacks run after the promise callbacks that are queued, where Node runs them first. Signal events like `SIGINT` and `SIGTERM` are not emitted, so a signal ends the app even with a listener. `loadEnvFile()` does nothing, and `util.parseEnv()`, `dlopen()`, `setuid()`, `setgid()` and `getgroups()` don't exist |
| Error stacks | `error.stack` has the JavaScriptCore format, lines like `name@file:line:column` without the `Error: message` line, and `Error.prepareStackTrace()` is not called |
| Timers | The main process runs until it quits, so `ref()` and `unref()` have no effect there. In `worker_threads` workers, `unref()` lets the worker end while the timer is pending |
| `perf_hooks` | `performance` records marks, measures and `timerify()` entries only, with no resource timing. In the main process on Windows and Linux, `eventLoopUtilization()` counts time spent drawing windows as idle |
| `worker_threads` | Workers get the environment of the app process, not the parent's `process.env`, so `SHARE_ENV` and the `env` option have no effect. The `argv`, `execArgv`, `stdin`, `stdout`, `stderr` and `resourceLimits` options are ignored. A `BroadcastChannel` in a page only reaches channels of the same page. A `MessagePort` can't be transferred to a worker, and `setEnvironmentData()`, `getEnvironmentData()` and `markAsUntransferable()` don't exist |
| `fs` | File descriptors are `@pierre/apps` handles, not OS descriptors, except the ones a process inherited. `statfs()` doesn't work on Windows. `glob()` takes `*`, `?`, `[...]`, `{a,b}` and `**`, without extglobs or `{1..3}` ranges, and `fs.promises.glob()` yields its matches after the walk ends. `openAsBlob()` reads the whole file into memory. `readableWebStream()` of a FileHandle returns a default stream, not a byte stream. `fs.promises.writeFile()` doesn't take streams or async iterables. `watch()` can report both `rename` and `change` for one change. `fs.constants` has no `S_I*` mode bits, and of the `O_` flags only `O_RDONLY`, `O_WRONLY`, `O_RDWR`, `O_CREAT`, `O_TRUNC`, `O_APPEND` and `O_EXCL` |
| `child_process` | `fork()` starts the app's executable with `ELECTRON_RUN_AS_NODE`. It runs a script that the build can find, like `import.meta.resolve('./child.ts')` or `path.join(__dirname, 'child.ts')`, or any file with `execPath: 'node'`. IPC uses Node's `json` serialization, so a real Node.js parent or child can be on the other side. `serialization: 'advanced'` and sending sockets or servers throw, and so does `'ipc'` on Windows. Other `stdio` entries past 2 are `'pipe'` socket pairs. The `uid` and `gid` options throw on Windows. The child's `stdout` and `stderr` are readable streams, not sockets |
| `crypto` | Hashes are `md5`, `sha1`, `sha224`, `sha256`, `sha384` and `sha512`. HMAC, `pbkdf2()` and `hkdf()` support all of them. Ciphers are `aes-128-gcm`, `aes-256-gcm` and `chacha20-poly1305` with a 12-byte IV, and a cipher keeps the message in memory until `final()`. A decipher takes only a 16-byte authentication tag. Keys are RSA, EC P-256 and P-384, and Ed25519. Encrypted keys, compressed EC points and EC private keys without their public key can't be read, and keys are not exported encrypted. P-256 keys sign with SHA-256 and P-384 keys with SHA-384. RSA keys sign with 2048 to 4096 bits, and RSA-PSS salts are as long as the digest. `generateKeyPair()` makes `ec` and `ed25519` keys only. There is no Diffie-Hellman, ECDH, `X509Certificate`, `KeyObject.from()`, `publicEncrypt()`, `privateDecrypt()`, `generatePrime()` or `argon2()`. `crypto.subtle` has SHA digests, HMAC, AES-GCM, PBKDF2, HKDF, Ed25519, ECDSA (P-256 with SHA-256, P-384 with SHA-384), RSASSA-PKCS1-v1_5 and RSA-PSS, with `raw`, `jwk`, `spki` and `pkcs8` keys. `wrapKey()` and `unwrapKey()` wrap with AES-GCM keys only. It can't generate RSA keys, and it has no AES-CBC, AES-CTR, AES-KW, RSA-OAEP, ECDH or X25519. A private key is checked when it signs, not when it is imported, and `deriveBits()` runs on the calling thread |
| `zlib` | Gzip, deflate and raw deflate only, there is no Brotli or Zstd. `params()` keeps the old level when the new one needs a different strategy. The `strategy` and `memLevel` options are ignored, and so is `finishFlush` outside streams. Streams compress on the JavaScript thread |
| `os` | `cpus()` times are 0, and so is `speed` on Macs with Apple silicon. On Windows, `constants.errno` has the numbers of libuv, `networkInterfaces()` returns `{}`, `loadavg()` returns zeros, `version()` returns `Windows`, and `getPriority()` and `setPriority()` throw |
| `dns` | `resolve*()`, `reverse()`, `lookupService()` and `Resolver` use the system resolver library and don't work on Windows. `setServers()` takes IPv4 servers only, timeouts are rounded up to seconds, and `Resolver` has no `setLocalAddress()` |
| `http`, `https` | `request()` uses `fetch`. It sends the body when `end()` is called, follows redirects, decodes gzip responses (without their `content-encoding` header) and reports the standard status text. It sends header names in lower case, adds `accept` and `accept-encoding`, sends no body with `GET` and `HEAD`, and can't upgrade or `CONNECT`. Responses have no trailers. `Agent` exists, but requests don't use its sockets. Servers listen on TCP ports only, by default on `0.0.0.0`. They send header names in lower case, send no trailers and have no `writeEarlyHints()`. They emit `upgrade` only for WebSocket requests, which only `ws` can take, and don't emit `connect`, `checkContinue` or `checkExpectation`: `Expect: 100-continue` gets its answer at once. `https.createServer()` throws, because `@pierre/apps` has no TLS server. `https.request()` checks certificates against the system roots. `rejectUnauthorized`, `ca`, `cert` and `key` are ignored, so servers with self-signed certificates fail |
| `net` | The default host is IPv4. `'lookup'` fires only when a connection succeeds, with the address that answered, and there is no automatic family selection. Local sockets and named pipes don't work on Windows |
| `node:sqlite` | No extensions, limits, `Session`, `function()`, `aggregate()` or `location()` |
| Node-API | Addons get version 8. `napi_get_uv_event_loop()` fails, because there is no libuv loop |
| `readline` | Reads lines from streams. There is no terminal line editing, history or completion |
| `util.inspect()` | The state of a Promise, the items of a Map or Set iterator and Proxy details are not shown |
| `TextDecoder` | Decodes `utf-8`, `utf-16le`, `utf-16be` and `windows-1252` (also named `latin1`), as in pages. Other encodings throw a `RangeError` |
| `assert` | A failed comparison shows both values, not a diff. `ifError()` throws the error that it gets, not an `AssertionError` |
| `util.types` | `isExternal()` always returns `false`, and `isProxy()` returns `false` for a revoked Proxy |
| `buffer` | `kMaxLength` is 2^32 - 1, the JavaScriptCore limit. `transcode()` converts between `ascii`, `latin1`, `utf16le` and `utf8` |
| `tty` | `process.stdin` reads descriptor 0 as a file stream, and its `setRawMode()` does nothing, so a terminal gives whole lines. `tty.ReadStream` throws. `tty.WriteStream` works for descriptors 1 and 2 when they are terminals. On Windows, `columns` and `rows` are always 80 and 24, and `resize` is not emitted |
