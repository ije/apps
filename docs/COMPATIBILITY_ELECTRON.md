# Electron Compatibility

These parts differ from Electron:

| Feature | Support |
|---|---|
| Platforms | `activate`, `open-url`, `open-file`, `second-instance`, the about panel, login items, the single instance lock, `clipboard`, `dialog`, `shell`, `Menu`, `Tray`, `Notification`, `globalShortcut`, `safeStorage`, `powerMonitor`, `powerSaveBlocker`, `systemPreferences` and `screen` work on macOS only. On Windows and Linux the events don't fire, the methods throw an error, and `Notification` emits `failed`. `nativeTheme` returns light defaults there |
| Exports | `BaseWindow`, `BrowserView`, `ImageView`, `TouchBar`, `ShareMenu`, `MessageChannelMain`, `MessagePortMain`, `webFrameMain`, `crashReporter`, `contentTracing`, `netLog`, `inAppPurchase` and `pushNotifications` are not supported. Importing them fails at build time |
| `utilityProcess` | `fork()` runs the script headless with the Node.js APIs, like `child_process.fork()`. Messages are copied as JSON, not by structured clone, and `postMessage()` can't transfer `MessagePortMain` objects. `serviceName` and the other Chromium options are ignored. A child stopped by a signal exits with the signal number as its code. Not supported on Windows |
| `protocol` | `handle()` answers `BrowserWindow` `loadURL()` and `net.fetch()` in main, and the response loads as an HTML string. Pages can't load files from such a scheme by `src` or `href` |
| `autoUpdater`, `desktopCapturer`, `webFrame` | `autoUpdater.checkForUpdates()` emits `error`, as Electron does in an unsigned app. `desktopCapturer.getSources()` returns no sources. `webFrame` always reports a zoom of 1, and its setters and `insertCSS()` do nothing, so use `webContents` to zoom and insert CSS. It has no `executeJavaScript()`, frames or spell check |
| `process` | `process.type` is `browser` in main and `renderer` in preload scripts. `process.versions.electron` is `40.0.0`, the first Electron release on Node.js 24 |
| Preload scripts | `preload` in `package.json` runs a module in each bundled page's isolated preload context. Page imports of that file receive its exports through the context bridge. A page can also declare `<script type="preload">`, inline or with `src`. There is no `webPreferences.preload`. Preloads run only in pages that ship with the app: bundled `apps:///` pages and files in the app folder. HTML strings from `load()` and other files get no preload. In the preload, `document` is a proxy for the page DOM: values are copied, page objects are handles, and functions can't be passed to the page this way. Like Electron's, a preload gets only `contextBridge`, `ipcRenderer`, `webUtils`, `webFrame`, `nativeImage`, `clipboard` and `shell` of the Electron modules, with `terminal` of `@pierre/apps` for the sessions of `<terminal>` elements, and main process modules like `app`, `BrowserWindow`, `dialog` and `Menu` are `undefined` |
| `loadFile()`, `load()` | A relative path is relative to `app.getAppPath()`. In main, `loadFile('<name>.html')` with a string literal is bundled like `import.meta.resolve()`, so its scripts, stylesheets and preload work in dev and built apps. Other paths load the file as it is, without its `src` scripts and linked stylesheets. Both return a Promise. A failed load rejects with `ERR_FILE_NOT_FOUND` or `ERR_FAILED` and emits `did-fail-load`. `loadURL()` takes `apps:`, `file:` and `data:text/html` URLs and the schemes of `protocol.handle()`, and rejects others with `ERR_DISALLOWED_URL_SCHEME`: use `WebContentsView` for websites |
| Threads | On macOS the main script runs on the main thread and each `BrowserWindow` on its own render thread, with its own JavaScriptCore VM, heap and event loop. A busy main script or window stops no frames in other windows, and a busy page stops no menus, window drags or window calls. They are threads, not OS processes, so a crash in native code ends the whole app. Pages share no globals, as in Electron, but they share web storage. A key that a busy page doesn't answer within 100 ms also goes to AppKit, so a menu shortcut can fire. `before-input-event` runs on the main thread before the page gets the key. As in Electron, `preventDefault()` doesn't stop an input method that composes text. While a main script waits in a nested loop, like `dialog.showMessageBoxSync()`, the event doesn't fire and keys go to the page. `close()` and quitting don't wait for a running page script, and stop it within about 100 ms. Native addons and `node:ffi` calls in preload scripts run on the render thread, so they can't use AppKit. On Windows and Linux everything shares the main thread |
| IPC | Values follow structured clone. Functions, symbols and promises throw `An object could not be cloned.`, but `contextBridge` values can hold them. Listeners run in a later task of the receiver, in send order. Exceptions in `ipcMain` listeners, and in `closed`, `destroyed` and `window-close` listeners, go to `uncaughtException`, or to the console. `ipcRenderer` has `send()`, `sendSync()` and `invoke()`, but no `postMessage()` or `sendToHost()`, so there are no `MessagePort`s and `event.ports` is empty. `contextBridge` has no `exposeInIsolatedWorld()`. `mainFrame.ipc` is the same object as `webContents.ipc` |
| `BrowserWindow` `webContents` | `print()` is not supported, and `debugger` is only for guests. `session` is the default session. `executeJavaScript()` works, while page code still can't run strings. Zoom is per window, not per origin, and `zoom-changed` is not emitted. `setWindowOpenHandler()` opens only bundled pages and local files, so other URLs are denied: open them with `shell.openExternal()` in the handler. `window.open()` returns `null` or an object with only `closed` and `close()`. There is no `postMessage()`, `findInPage()`, `printToPDF()`, `savePage()`, `downloadURL()` or `close()`. `setAudioMuted()`, `setUserAgent()`, `sendInputEvent()`, `startDrag()`, `stop()` and `closeDevTools()` do nothing. Events are only `did-start-loading`, `did-navigate`, `dom-ready`, `did-finish-load`, `did-fail-load`, `did-stop-loading`, `did-create-window`, `before-input-event`, `input-event`, `context-menu`, the `<webview>` events and `destroyed`: `page-title-updated` goes to the window only, and there is no `will-navigate`, `console-message`, `render-process-gone` or `unresponsive`. A `beforeunload` listener can't stop a close. `mainFrame` has no child frames, and `navigationHistory` has one entry |
| `WebContentsView` | Uses the system WebKit (WKWebView, WebView2 or WebKitGTK), so `did-fail-load` codes are the platform's, for example `NSURLError` codes on macOS. `will-navigate` can be cancelled on macOS only, and `will-redirect`, `before-input-event`, `context-menu` and `audio-state-changed` are not emitted. There is no Chrome DevTools Protocol, so tools like Playwright can't connect. `debugger.sendCommand()` answers only `Runtime.evaluate`, `Page.captureScreenshot`, `Page.reload`, `Target.getTargetInfo` and `Emulation.setEmulatedMedia`, accepts the `enable` commands and some `Emulation` settings that do nothing, and rejects others. With `setWindowOpenHandler()`, `allow` opens the page in a separate browser window and ignores `overrideBrowserWindowOptions`. `webPreferences` takes `partition`, `javascript`, `devTools` and the safe default values of the security keys, like `nodeIntegration`, `contextIsolation`, `sandbox` and `webSecurity`. Other keys throw an error. `send()` does nothing, because a guest has no preload. On macOS, `executeJavaScript()` on a page whose CSP blocks `eval` runs in an isolated world, which can't see page globals. On Windows and Linux it fails on such pages. `loadFile()` can't load bundled pages. A page's `window.apps.postMessage(data)` arrives as `ipc-message` with the channel `message` |
| `session` | Applies to the system web views of its partition, not to `BrowserWindow` pages. `cookies` and `clearStorageData()` work there, and `clearStorageData()` and `clearCache()` clear all data, whatever their options. `webRequest` listeners, permission handlers, `setProxy()`, `setDownloadPath()`, `setCertificateVerifyProc()` and the spell checker settings do nothing, and `will-download` and `cookies` `changed` don't fire. There is no `loadExtension()`, `downloadURL()`, `preconnect()`, `clearData()` or `registerPreloadScript()` |
| `Menu` | Every role has Electron's label and accelerator. `reload` and `forceReload` reload the focused window, and `resetZoom`, `zoomIn` and `zoomOut` zoom it. `shareMenu` is a normal item that does nothing. The default menu has no reload or zoom items. Changes to a `MenuItem` after `setApplicationMenu()` need another `setApplicationMenu()`. Menu icons take file paths. Sublabels require macOS 14.4 or later. `popup()` takes `x`, `y`, `positioningItem` and `callback`, and shows the menu in the focused window. `closePopup()` does nothing, and there is no `Menu.sendActionToFirstResponder()`. Media key accelerators are not shown in menus, and `globalShortcut.register()` returns `false` for them |
| `Tray` | The constructor, `setImage()` and `setPressedImage()` take file paths. Use an empty string for a title-only tray. Titles support plain text and font options. Call `setContextMenu()` again after editing menu items. Popup menus open at the tray icon |
| `shell`, `clipboard` | `shell` has only `openExternal()`, `openPath()` and `showItemInFolder()`, so there is no `trashItem()` or `beep()`. `openExternal()` opens only `http`, `https`, `mailto` and `tel` URLs, and ignores its options. The clipboard reads and writes text, HTML, RTF, PNG images, and raw pasteboard types with `readBuffer()` and `writeBuffer()`. `readImage()` also reads TIFF. `has()` takes a MIME type or a pasteboard type like `public.png`. Bookmarks, find text and the `selection` clipboard are not supported |
| `Notification` | Needs an app bundle identifier, so in `apps run` `show()` emits `failed`. Only `title`, `body` and `silent` apply: `subtitle`, `icon`, `sound`, `actions` and `hasReply` are ignored, and `action` and `reply` don't fire |
| `dialog` | Open dialogs take the `openFile`, `openDirectory`, `multiSelections` and `createDirectory` properties and ignore the others, like `showHiddenFiles`. Open and save dialogs are separate panels, not sheets of the window, and an async message box is a sheet of the focused window. `icon`, `signal` and `securityScopedBookmarks` are ignored |
| `powerMonitor` | Emits `suspend`, `resume`, `shutdown` and `thermal-state-change` only, not `on-ac`, `on-battery`, `lock-screen`, `unlock-screen` or `speed-limit-change` |
| `systemPreferences` | `subscribeNotification()`, `postNotification()` and their local and workspace forms are not supported. `askForMediaAccess()` needs `NSCameraUsageDescription` or `NSMicrophoneUsageDescription` in the app's Info.plist, which `apps build` doesn't add, and rejects without it |
| `net` | `request()` follows redirects, or fails on them with `redirect: 'error'`. `redirect: 'manual'`, the `redirect` and `login` events and the `session`, `partition`, `credentials` and `useSessionCookies` options are not supported. `resolveHost()` uses the system resolver and takes only `queryType`. `isOnline()` checks for a network interface with a routable address and is always `true` on Windows |
| `webUtils` | `getPathForFile()` knows only files dropped on a page |
| `open-url` | The URL scheme must be in the app's `Info.plist`, which `apps build` doesn't add. `setAsDefaultProtocolClient()` works only in a built app |
| `relaunch()` | Works in built apps. `apps run` ignores it |
| `setPath()`, `setName()` | Change only the values that `app` returns. Web storage keeps its own location. `getPath()` throws for `module`, `recent` and `crashDumps` |
| `commandLine` | Switches can be added and read, but they don't change apps. `disableHardwareAcceleration()` does nothing, because apps always draws on the GPU |
| Login items | Need macOS 13 and a built app. Only `openAtLogin` and `status` are returned |
| Images | `dock.setIcon()` and `iconPath` take a file path. `nativeImage` decodes, resizes, crops and encodes images, and has no scale factors, named images or `createThumbnailFromPath()`. `app.getFileIcon()` returns an icon on macOS only |
| `BrowserWindow` options | `webPreferences`, `autoHideMenuBar`, `titleBarOverlay`, `roundedCorners`, `acceptFirstMouse`, `tabbingIdentifier`, `disableAutoHideCursor`, `enableLargerThanScreen`, `thickFrame` and `paintWhenInitiallyHidden` are ignored. The others are `width`, `height`, `x`, `y`, `useContentSize`, `center`, `minWidth`, `minHeight`, `maxWidth`, `maxHeight`, `resizable`, `movable`, `minimizable`, `maximizable`, `closable`, `focusable`, `alwaysOnTop`, `fullscreen`, `skipTaskbar`, `show`, `parent`, `modal`, `title`, `icon`, `backgroundColor`, `hasShadow`, `opacity`, `frame`, `transparent`, `titleBarStyle`, `trafficLightPosition`, `vibrancy` and `visualEffectState`. Other options, like `fullscreenable`, `kiosk` and `type`, throw an error. `titleBarStyle` is `default`, `hidden` or `hiddenInset`. As in Electron on macOS, `skipTaskbar` and `icon` do nothing there. `setVibrancy()` ignores `animationDuration` |
| `BrowserWindow` state | Getters return cached values. A setter changes them at once, and the real values arrive with the window events. For example, `getPosition()` is correct after `center()` once `move` fires. `resized` also fires after `setSize()` and `maximize()` |
| Frameless windows | On Linux, `frame: false` and a hidden title bar remove the window border, so the window can't be resized from its edges |
| `will-resize`, `will-move` | Fire for resizes and moves by the user on macOS, not while a main script waits in a nested loop. `details.edge` is `right` or `bottom`, and `preventDefault()` doesn't stop a move, both as in Electron on macOS |
| Recent documents | `app.addRecentDocument()` needs the file type in the app's `Info.plist`, which `apps build` doesn't add |
| `BrowserWindow` on Windows and Linux | Sizes and bounds are the content area. `setPosition()`, `center()`, `hide()`, `showInactive()`, `moveTop()`, `blur()`, `unmaximize()`, the size limit setters, `setResizable()`, `setMovable()`, `setMinimizable()`, `setMaximizable()`, `setClosable()`, `setAlwaysOnTop()`, `setHasShadow()`, `setIgnoreMouseEvents()`, `setFocusable()`, `setAspectRatio()`, `setProgressBar()`, `flashFrame()`, `setSkipTaskbar()`, `setIcon()`, `setMenu()` and `removeMenu()` throw an error, as do `setOpacity()` on Windows and `setVisibleOnAllWorkspaces()` on Linux. The `opacity`, `hasShadow`, `focusable`, `skipTaskbar`, `icon` and `vibrancy` options are ignored, and on Linux also the size limit, `maximizable`, `closable` and `alwaysOnTop` options. Modal windows don't block their parent, and on Wayland `parent` has no effect. As in Electron, `setVibrancy()` does nothing there, and neither do `setOpacity()` and `setContentProtection()` on Linux. `isMinimized()` is always `false`, and `restore()` focuses the window |
| `getAppMetrics()` | Returns one entry for the whole app, with its memory only. The CPU values are 0 |
| Not supported | Jump lists, user activities, `setAppLogsPath()`, GPU info, proxy, certificates and accessibility APIs. In `app`: `isInApplicationsFolder()`, `moveToApplicationsFolder()`, `getApplicationNameForProtocol()`, `setSecureKeyboardEntryEnabled()`, and the events `did-become-active`, `did-resign-active`, `login`, `render-process-gone`, `child-process-gone` and `session-created`. `removeAsDefaultProtocolClient()` does nothing. In `BrowserWindow`: `setKiosk()`, `setFullScreenable()`, `setSimpleFullScreen()`, `setEnabled()`, `getBackgroundColor()`, `capturePage()` (use `webContents.capturePage()`), tabs, properties like `title` and `resizable` (use the methods), and the events `unresponsive`, `swipe`, `app-command` and `new-window-for-tab`. `setAutoHideCursor()`, `setTitleBarOverlay()`, `setOverlayIcon()`, `setSheetOffset()`, `invalidateShadow()`, `moveAbove()` and `setRepresentedFilename()` do nothing, and `getNativeWindowHandle()` returns the window ID, not an `NSWindow` |
