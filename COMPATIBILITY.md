# Compatibility

## DOM

Pages get the standard DOM API (nodes, elements, events, ranges, selection, observers, shadow DOM and custom elements). These parts differ from browsers:

| Feature | Support |
|---|---|
| `NodeList`, `HTMLCollection` | Static arrays with `item()`. They don't update when the tree changes |
| `CDATASection`, `ProcessingInstruction` | Not supported. `Attr` is not a `Node` |
| Named access | Elements are not globals by their `id`, so `window.foo` for `<div id="foo">` is `undefined`. Use `document.getElementById()`. Forms don't have their controls as properties, so `form.username` is `undefined`. Use `form.elements.username` |
| `DOMParser`, XPath, XSLT | `DOMParser` parses `text/html` and `image/svg+xml`. SVG goes through the HTML parser: `documentElement` is the `<svg>`, which stays inside a `<body>`, and errors make no `<parsererror>`. XPath and XSLT are not supported |
| `*AttributeNS()` | The namespace is ignored |
| Element names | `createElement()` and `createElementNS()` take only names of ASCII letters, digits and `-` that start with a letter. Others, like `a_b` or `x:y`, throw an `InvalidCharacterError` |
| `<template>` | Parsed children move into `content` when `content` is first read |
| `eval()`, `new Function()` | Throw an `EvalError` in pages and page workers, as do the constructors of async and generator functions. The `jsExecute` feature allows them |
| `ShadowRealm` | Needs the `jsExecute` feature. A realm has only the JavaScript built-ins. `importValue()` loads `data:` and `blob:` URLs, and `http` and `https` URLs with `httpImport`, but not the modules of the app. Wrapped functions don't keep `name` and `length` |
| `import()` | A string literal imports a bundled module. Other specifiers stay in the code and load when they run: `data:` and `blob:` URLs with the `jsExecute` feature, `http` and `https` URLs with `httpImport`. Remote modules can import other modules only by URL |
| Remote scripts and stylesheets | `<script src>`, `<link rel="stylesheet">`, JavaScript imports and CSS `@import` with `http` or `https` URLs need the `httpImport` feature. `apps build` downloads them into the app |
| Links added by scripts | A `<link>` with `rel` `stylesheet`, `preload` or `modulepreload` that a script inserts doesn't load and fires `error`. Only the stylesheets in the page HTML apply, and changing their `href` doesn't load another file |
| Classic scripts | `<script>` without `type="module"` runs as a classic script, with global `var` and `function`, sloppy mode and `this` as `window`. Scripts without `defer` or `async` run before module scripts. Classic scripts are bundled as written: no TypeScript or JSX, and their `import()` is not bundled. `nomodule` scripts don't run |
| Root-relative paths | In `src`, `srcset`, `href`, CSS `@import` and `url()`, a path that starts with `/` is relative to the app folder and cannot leave it. As in browsers, `\` counts as `/` |
| Inline event attributes (`onclick="..."`) | Not run. `el.onclick = fn` and `addEventListener` work |
| HTML parsing | Follows the HTML5 tree builder, except MathML and framesets |
| Navigation | Pages can go to bundled `apps:///` pages and local `file:///` files only. Other URLs throw. A click on a link goes to such a page or to a fragment of the page, and links to other URLs do nothing. Use `WebContentsView` or `shell.openExternal()` for websites |
| `<iframe>` | Shows its page in a system web view (WKWebView, WebView2 or WebKitGTK) above the page, so it has no `contentDocument` or `contentWindow`, and CSS can't clip, blend or fade it. It hides while it or an ancestor has `opacity: 0` or `visibility: hidden`. `src` takes `http`, `https`, `file`, `data` and `about` URLs, so pages of the app don't load |
| Replaced elements | `img`, `svg`, `canvas`, `video`, `audio`, `iframe`, `embed` and `object` compute `display` as `inline-block`, where browsers have `inline`. They lay out the same |
| `<object>`, `<embed>` | Load no plugins or documents. An `<object>` shows its fallback content, or an empty 300×150 box when it has neither `data` nor fallback content, and an `<embed>` with a source is an empty 300×150 box |
| `<webview>` | Shows its page in a system web view above the page, like `<iframe>`, so CSS can't clip, blend or fade it. `src`, `partition`, navigation, zoom, `loadURL()`, `executeJavaScript()`, `insertCSS()` and the load, navigation and title events work. `preload`, `webpreferences`, `allowpopups`, `send()` and `ipc-message` don't. A `<webview>` can't load `file:` URLs: such a load fails with `ERR_ACCESS_DENIED`. Main gets `will-attach-webview` and `did-attach-webview`, and the `partition` is the only preference that applies |
| `Worker` | A worker has the APIs of the script that creates it: workers of the main process and of preload scripts get the Node.js APIs, and page workers don't. A worker is bundled, and compiled by `--aot`, when the build can read its file from the code: `new URL('./work.ts', import.meta.url)`, `import.meta.resolve('./work.ts')`, `import.meta.url`, `__filename`, and paths made from `__dirname` or `import.meta.dirname` with `path.join()`, `path.resolve()`, `+` or a template string, also inside `fileURLToPath()`, `String()` or `.href`. `require.resolve()` and `import.meta.resolve()` also find a file of a package, like `require.resolve('pkg/worker.js')`. A local file that is missing fails the build. Other workers load `data:` and `blob:` URLs, and outside pages local files, as classic scripts. Remote scripts are rejected. A global `Worker` runs until `terminate()` or `close()`, and one from `node:worker_threads` ends when it has no work left. Messages follow structured clone, and they can hold `Blob`, `File`, `ImageData`, `ImageBitmap` and `CryptoKey` objects. Only `ArrayBuffer`, `ImageBitmap` and `OffscreenCanvas` can be transferred, so a `MessagePort` can't go to a worker. A transferred `ArrayBuffer` moves without a copy, and a `SharedArrayBuffer` shares its memory with the worker. For WebAssembly threads, a `WebAssembly.Module` and a shared `WebAssembly.Memory` also go to workers. As in browsers, `Atomics.wait()` throws in a page. It works in workers and in the main process. `Atomics.waitAsync()` doesn't exist |
| Private networks | `fetch()` and `WebSocket` in pages can't reach loopback, LAN and other private addresses, except a loopback address and port that one of the app's own servers is bound to. A server on `0.0.0.0` covers `127.0.0.1` for its port, and one on `::` covers `::1`. The `localNetwork` feature allows them, for apps with servers in child processes |
| Long scripts | A page script that runs for more than 10 seconds without returning is stopped, so one page cannot freeze the app |
| Origin private file system | `navigator.storage.getDirectory()` keeps files in memory, so they are lost when the page reloads or the app quits |
| Forms | A submit that is not canceled sends nothing and does not navigate, so handle `submit` and call `preventDefault()`. `method="dialog"` closes its dialog |
| `attachInternals()` | Has `setFormValue()`, `setValidity()`, `validity`, `checkValidity()`, `form`, `labels` and `states`. `:state()`, the `formResetCallback` and `formDisabledCallback` reactions and ARIA properties of the internals have no effect |
| Form pseudo-classes | `:valid` and `:invalid` match `input`, `select`, `textarea` and submit buttons, not `form` and `fieldset`. A `<select>` checks its validity again when its selection or attributes change, not when options are added or removed. `:user-valid`, `:user-invalid` and `:autofill` never match, and `:indeterminate` doesn't match radio buttons. `:default` finds the default button of the ancestor `<form>` only, not of a `form` attribute |
| Date and time inputs | Show and edit the value as plain text, like `2026-10-31`, with no picker, and are as wide as a text field |
| Styled ranges and progress bars | With `appearance: none`, `::-webkit-slider-runnable-track`, `::-webkit-slider-thumb`, `::-webkit-progress-bar` and `::-webkit-progress-value` draw with their size, `margin-top`, background color, one border and radius. Their background images, shadows and `:hover` and `:active` styles are not drawn. A `<meter>` with `appearance: none` draws nothing |
| `ns-*` input types | `ns-button`, `ns-switch`, `ns-range`, `ns-text`, `ns-search`, `ns-color` and `ns-date` show `NSButton`, `NSSwitch`, `NSSlider`, `NSTextField`, `NSSearchField`, `NSColorWell` and `NSDatePicker` on macOS. An `ns-range` with a `step` attribute shows an `NSStepper`. On other platforms they are `button`, `checkbox`, `range`, `text`, `search`, `color` and `date` inputs, and `type` returns that type everywhere. Like web views, the controls draw above the page: CSS sets their size and place, and ancestors with `overflow` clip them, but other styles, transforms and boxes painted over them don't apply. They are light unless their `color-scheme` allows dark, and with both they follow the window. Presses arrive as `click`, and edits as `input` and `change`. The page can't focus them, so `focus()` doesn't move the keyboard to a native field |
| `<input type=file>` | `click()` opens the system panel only while the page handles user input, on macOS. Files over 64 MB are left out, and `accept` filters only by `.ext` and `image/*`. `webUtils.getPathForFile()` doesn't know picked files. `::file-selector-button` sets the padding, margin, borders, colors and radius of the button. An `<input type=image>` shows no `alt` text |
| `alert()`, `confirm()`, `prompt()` | On macOS they show a message box of the app and wait for the answer, in pages, preload scripts and the main process. On Windows and Linux, and in pages of an app with a Rust main, they show nothing and return `undefined`, `false` and `null`. Workers and headless scripts don't have them |
| `TextDecoder` | Decodes `utf-8`, `utf-16le`, `utf-16be` and `windows-1252`. Other encodings, like `gbk` and `shift_jis`, throw a `RangeError` |
| `XMLHttpRequest` | Runs on `fetch`. Synchronous requests throw `InvalidAccessError`, upload `progress` fires only at the end, and response headers are not filtered by CORS |
| Clipboard API | `navigator.clipboard` reads and writes text only, while a page script runs from the app's event loop. `write()` needs a `text/plain` item and ignores its other types, so images are rejected |
| File drags | Files dragged from other apps fire `dragenter`, `dragover`, `dragleave` and `drop`. As in browsers, `drop` fires only if the last `dragover` was canceled and files can be read only in `drop`. The system cursor always shows a copy badge, and a file input doesn't take dropped files by default |
| Hit testing | A rotated or skewed box takes pointer events in its bounding rectangle, and an SVG shape in its whole box |
| `navigator` | Has `userAgent`, `platform`, `language`, `languages`, `hardwareConcurrency`, `onLine`, `cookieEnabled`, `maxTouchPoints`, `clipboard`, `storage`, `gpu`, `sendBeacon` and the fixed legacy fields `vendor`, `appName`, `appCodeName`, `appVersion`, `product`, `webdriver` and `pdfViewerEnabled` |
| `document.cookie` | Keeps cookies in memory for the page only. They are not saved and not sent with requests |
| `requestIdleCallback()` | Runs its callback after a 1 ms timer |
| `window.screen` | Describes the display of the window as of its last frame or window change, and on Linux the primary display, with `availWidth` equal to `width`. `window.screenX`, `screenY`, `screenLeft`, `screenTop`, `outerWidth` and `outerHeight` give the window frame. `colorDepth` and `pixelDepth` are always 24 and `orientation.angle` is 0. `orientation.lock()` rejects, and `change` events don't fire. Preload scripts and workers don't have them |
| `<select>` | On macOS a press, Space or `showPicker()` opens the options in a system menu, as in Safari, so CSS doesn't style the list. On Windows and Linux there is no list. Everywhere, arrow keys and typing change the selected option |
| Top layer | Modal dialogs, popovers and fullscreen elements paint above the page. `::backdrop` draws its background, opacity and `backdrop-filter` over the whole viewport, and ignores its other properties. Its transitions run, also from `@starting-style`, but its animations don't. As in browsers, a closed dialog or popover stays in the top layer while its `overlay` transition runs. As in Chromium, the topmost modal dialog, or else the fullscreen element, makes the rest of the page inert, popovers above it too. `requestFullscreen()` needs no user gesture and resolves before the window's fullscreen animation ends |
| `execCommand()`, undo | `execCommand()` supports `copy`, `cut`, `paste`, `selectAll`, `insertText`, `delete`, `forwardDelete`, `undo` and `redo`. Formatting commands like `bold` return `false`. Clipboard commands work only while the page handles user input. Undo doesn't join paragraphs that Enter split in a contenteditable |
| `<video>`, `<audio>` | Need the `media` feature. They play MP4, MOV, WebM, Matroska, Ogg, MP3, WAV, FLAC and AAC files with H.264, HEVC, VP8, VP9, AAC, MP3, Opus, Vorbis, FLAC, ALAC and PCM. AV1 plays only with hardware decoding. `controls` draws no controls, rotation metadata is ignored and `playbackRate` changes the pitch. Remote and `blob:` sources download fully before they play. `srcObject`, Media Source Extensions, text tracks and `requestVideoFrameCallback()` are not supported. Frames are scaled to fit 8192 pixels per side after the pixel aspect ratio is applied, and late frames are skipped |
| `simpleAudio` | Plays `<audio>` without FFmpeg, for apps that only need short sounds and have no `media` feature. It plays only WAV files with 8, 16, 24 or 32-bit PCM samples, or 32 or 64-bit float samples. `canPlayType()` returns an empty string for other types, and they fail with an `error` event. A file with more channels than the output drops the extra ones |
| Web Audio | `AudioContext` plays whole sounds through `<audio>`, so it needs the `media` or `simpleAudio` feature. With `simpleAudio` it decodes only WAV data. It has `decodeAudioData()`, `createBufferSource()` and `createGain()`. Buffers keep the encoded file, so they have no samples, and other nodes don't exist |
| Canvas 2D | `filter` is not supported: it keeps its value and draws nothing. `strokeText()` fills the text with the stroke style. Only the part of a shape inside the clip casts a shadow, and a `shadowBlur` above 256 blurs like 256. A pattern takes the pixels of its image when it becomes `fillStyle` or `strokeStyle`, not when it is created. `measureText()` gives an emoji the width it has in page text. `drawImage()` draws an SVG image at the size it covers on the canvas, up to 4096 pixels per side. `toDataURL()` and `toBlob()` make PNG, and JPEG on macOS. Other types give PNG, as in browsers. The `hue`, `saturation`, `color` and `luminosity` composite operations can give other colors |
| `DOMMatrix` | Takes a string only in the `matrix()` and `matrix3d()` forms that `getComputedStyle()` returns |
| SVG geometry | `getCTM()` and `getScreenCTM()` use the `transform` attributes and the `viewBox`, not CSS transforms. `getTotalLength()` and `getComputedTextLength()` are not supported |
| `OffscreenCanvas` | Has `2d`, `webgpu` and `bitmaprenderer` contexts, in pages and page workers, but not in the main process, preload scripts and their workers. `getContext('webgl')` returns `null`. `convertToBlob()` makes a JPEG on macOS when asked, and a PNG for other types. The blob's `type` says which. A canvas that moved to a worker shows its frames one task after they are drawn, so a frame drawn across `await`s can show in parts. In workers, text uses installed fonts because `document.fonts` doesn't exist, and `requestAnimationFrame()` runs on a 16 ms timer |
| `createImageBitmap()`, `ImageBitmap` | Take images, SVG images, canvases, videos, bitmaps, `ImageData` and blobs. Pixels are stored premultiplied, so with `premultiplyAlpha: 'none'` a pixel with alpha 0 loses its color and other colors round. `colorSpaceConversion` is ignored, and EXIF orientation is not applied. `resizeQuality` is `pixelated` or bicubic. Messages to workers copy the pixels once or twice, even with `transfer`. `copyExternalImageToTexture()` writes only `rgba8unorm`, `bgra8unorm` and their `-srgb` formats |
| Web Animations | `ScrollTimeline` and `ViewTimeline` are not supported. Among pseudo-elements, only `::before` and `::after` animate. The `composite` of a keyframe is ignored, the effect's applies. CSS animations and transitions from `getAnimations()` play at rate 1, so changing `playbackRate` and `reverse()` throw, and transitions of `::backdrop` are not among them. Their `commitStyles()` also commits the values of script animations above them |
| Deep trees | Boxes nested more than 256 levels deep are not drawn |

## CSS

Pages use standard CSS, drawn by `@pierre/apps` on the GPU. Transforms, filters, blend modes, masks and clip paths paint through offscreen GPU layers.
These parts differ from browsers. The ones that don't work show an error in the Developer Tools console (`apps run -D`): properties and at-rules that `@pierre/apps` reads but does not apply, like `hyphens`, `orphans` and `@counter-style`, and values it rejects. `@supports` and `CSS.supports()` return false for them. As in browsers, a rejected value is dropped, so an earlier value of the property applies.

| Feature | Support |
|---|---|
| `transform-style: preserve-3d` | 3D children are flattened into the parent's plane |
| `filter: url()` | Only `<filter>` elements in the page, with `feGaussianBlur`, `feColorMatrix` and `feDropShadow`. An `feOffset` works only together with an `feGaussianBlur`, as a drop shadow |
| `clip-path: shape()` | Not supported |
| `background-clip: text` | Paints the text in the first color of the gradient |
| `border-image` | Not supported |
| `overflow-clip-margin` | Not supported |
| `background-attachment: fixed` | Works on the background of the page (`html`, or `body` when `html` has none). On other elements the layer scrolls with its box |
| `vector-effect: non-scaling-stroke` | Undoes the `viewBox` scale of the `<svg>`, but not transforms inside it |
| `line-height`, `vertical-align` in `::first-letter` and `::first-line` | Ignored. Sizes, colors and font styles work |
| `::before`, `::after` | Are not grid items when their grid has other items. Their `clip-path` shapes, `mask` and `outline` are not drawn, their background stays inside their border, and text doesn't flow around a floated one |
| Default font | Pages without a `font-family` use the system font, where browsers use Times. `ui-serif` and `ui-rounded` are the system font too |
| Text decoration | `text-decoration-skip-ink` is not applied: lines cross descenders. Wavy, dotted and double lines have slightly different shapes |
| `font-variant` | Only `normal` and `small-caps`. Small caps are capitals at 70% of the size |
| Line breaks | A soft hyphen (`&shy;`) gives no break. In `pre-wrap` text, lines break before their tabs are placed, so a break can be off |
| `float` | Floats that don't fit beside each other wrap to a new row, below the tallest float of the row before. Text next to a float doesn't move under it when the float ends, and a block after a float is narrowed beside it. A block that holds only floats is as tall as they are |
| Inline content in text | Inline boxes split across lines, and inline-blocks, images and controls sit in the line. A paragraph with a float, a positioned child, or an inline box with a transform, opacity or animation wraps as separate pieces, so it breaks before and after such a box. Text next to a new inline-block can move for one frame, until its size is known. `getClientRects()` of an inline box returns one rectangle, however many lines it spans |
| Multi-column layout | Columns break between child blocks, and a `column-span: all` box splits them. One paragraph doesn't split across columns, and margins at column breaks are kept |
| Tables | A `display: table-cell` box with no row or table parent gets no anonymous table, so such cells stack as blocks. `border-collapse` applies to `<table>` elements only. The background and border of a table also go around its caption. `getBoundingClientRect()` of a `<col>` is empty |
| `writing-mode: vertical-lr` | Lines are ordered right to left, like `vertical-rl` |
| Logical properties | `margin-inline-start`, `inline-size`, `block-size` and the other logical properties follow `direction` but not `writing-mode`, so in vertical text they map to the same sides and sizes as in horizontal text |
| Tailwind CSS v4 | `@import "tailwindcss"` compiles the classes in the page when they appear, with `@theme`, `@custom-variant`, `@utility` and `@apply`. `@plugin`, `@source`, `@config` and the `prefix()`, `source()` and `important` import options are not supported. An `@utility` that applies itself, directly or through other utilities, skips that `@apply`, where Tailwind reports an error |
| Liquid Glass | Needs macOS 26, and its press feedback macOS 27. Only boxes with uniform corners, no transforms or filters, and no clipping or other content above them get glass. Other boxes, and all boxes on other platforms, keep their CSS look. `bg-glass-interactive` doesn't turn glass on by itself, and only the tint utilities work with variants and `@apply`. `capturePage()` rejects frames with glass, and `<iframe>`, `<webview>` and `WebContentsView` show above it |
| SF Symbols | Monochrome. Missing symbols, and all symbols on other platforms, show an empty box of the same size |
| Overscroll | A trackpad bounces any box that scrolls at its edges, like Safari, with AppKit's curve. Boxes and pages with nothing to scroll and mouse wheels don't bounce. `scrollTop` and scroll events stay in range during a bounce. `overscroll-behavior` on the root element applies to the page, not on the body. `contain` and `none` also stop scrolling at boxes with `overflow: hidden` or nothing to scroll, as in Chromium |
| Scrollbars | Drawn as macOS overlay bars on all platforms. They show while the box scrolls or the pointer is on them, then fade out, and they take no space. The knob is light on a dark `color-scheme` or background. The macOS "Always" scroll bar setting is ignored. `scrollbar-width` and `scrollbar-color` work |
| `::-webkit-scrollbar` | Gives bars that always show and take space, as in Chromium. `-track`, `-thumb`, `-thumb:hover` and `-corner` use the background color, border, `border-radius` and `background-clip`. Buttons, other scrollbar states and background images are not drawn. `scrollbar-gutter: stable` works only with these bars |
| `app-region`, `-webkit-app-region` | `drag` and `no-drag` work as in Electron. The value is inherited, so `getComputedStyle()` returns it for children, and a box that only overlaps a drag area doesn't move the window |
| `mask-composite` | `intersect` works when all layers are axis-aligned linear gradients at their default size, which is how Tailwind builds masks. Other masks add their layers |
| `@font-face` | `local()` matches installed family names, not full or PostScript names. A face with `unicode-range` loads when the page text uses one of its characters. Subset faces of one font don't combine per character: the face that covers the most page text draws all of it. The `font-weight`, `font-style`, `font-stretch` and `font-display` descriptors are ignored, so a face is used with its own weight and style. Faces load before the page first draws or when `document.fonts` is read. Color fonts draw in one color, so sources with a color `tech()` are skipped |
| `border-radius` | Percentages in the corners of `<img>` content use the box's `width` and `height` properties, so they are off on images that are sized by their content |
| `aspect-ratio` | Applies to the border box, so a box with `box-sizing: content-box` and padding or borders gets another height |
| `direction: rtl` | Logical properties, text alignment, floats, flex rows, grid columns and block boxes follow the direction. Text that mixes directions is not reordered |
| `@scope` | `@scope` without a selector applies to the whole page, not to the parent of its `<style>`. Scope proximity doesn't affect the cascade |
| `:host-context()` | Not supported, like in Safari |
| Counters | `@counter-style` is not supported |
| Lists | A `list-style-image` gradient is not drawn |
| `<legend>` | In a `<fieldset>` with rounded corners, the legend is drawn inside the border instead of on it |
| Registered custom properties | `@property` values compute absolute lengths to `px`, and numbers, angles, times and percentages to their canonical form. Relative lengths like `2em` and colors keep their written form, so an inherited `2em` resolves with the font size of the element that uses it, and `getPropertyValue()` returns `red` where browsers return `rgb(255, 0, 0)` |
| Custom property animations | Only `@property` values with a `<length>`, `<number>`, `<percentage>`, `<length-percentage>`, `<color>`, `<angle>` or `<time>` syntax interpolate and transition. Other registered custom properties switch halfway in keyframes and don't transition, where browsers interpolate them |
| Transform animations | Lists that don't match function by function interpolate as matrices only when their lengths are in `px` and they have no `perspective()`. Other such lists switch halfway |
| Animations and `!important` | CSS and script animations override `!important` declarations, where browsers keep the important value. Transitions follow the standard |
| Animations out of view | Animations and transitions that only paint and can't move the box (rotate, scale, opacity, colors, shadows) pause while the box is outside the window or clipped away. They go on at the current time when the box comes into view, and fire no `animationiteration` events meanwhile |
| Composited animations | Animations and transitions of `opacity` and transforms draw without laying out the page, on macOS in Core Animation. `IntersectionObserver` sees such a box where the last full frame drew it. As in Chromium, `animationiteration` doesn't wake a page that never listened for it |
| `var()` fallbacks | Fallbacks nested more than 32 levels deep make the value invalid |
| Huge text | A glyph bigger than 2048 device pixels on a side draws from a smaller raster, so its edges are soft |
| `getComputedStyle()` | `grid-template-columns` and `grid-template-rows` return the computed values, not the used sizes in pixels. `background-image` keeps its URLs and gradient colors as written. `text-decoration-line` includes the lines a box gets from its ancestors. An explicit `overflow: visible` on a `<textarea>` stays `visible`, though the textarea scrolls like `auto` |
| CSSOM | `@import` works only in bundled CSS, so `CSSImportRule.styleSheet` is `null`. The `style` attribute keeps its text as written, where browsers rewrite it: `cssText` and property reads give the browser form |

## Electron API

These parts differ from Electron:

| Feature | Support |
|---|---|
| Platforms | `activate`, `open-url`, `open-file`, `second-instance`, the about panel, login items, the single instance lock, `clipboard`, `dialog`, `shell`, `Menu`, `Tray`, `Notification`, `globalShortcut`, `safeStorage`, `powerMonitor`, `powerSaveBlocker`, `systemPreferences` and `screen` work on macOS only. On Windows and Linux they throw an error. `nativeTheme` returns light defaults there |
| Exports | `crashReporter`, `BaseWindow` and `MessageChannelMain` are not supported. Importing them fails at build time |
| `utilityProcess` | `fork()` runs the script headless with the Node.js APIs, like `child_process.fork()`. Messages are copied as JSON, not by structured clone, and `postMessage()` can't transfer `MessagePortMain` objects. `serviceName` and the other Chromium options are ignored. A child stopped by a signal exits with the signal number as its code. Not supported on Windows |
| `protocol` | `handle()` answers `loadURL()` and `net.fetch()` in main. Pages can't load files from such a scheme by `src` or `href` |
| `autoUpdater`, `desktopCapturer`, `webFrame` | `autoUpdater.checkForUpdates()` emits `error`, as Electron does in an unsigned app. `desktopCapturer.getSources()` returns no sources. `webFrame` always reports a zoom of 1, and its setters do nothing, so use `webContents` to zoom |
| `process` | `process.type` is `browser` in main and `renderer` in preload scripts. `process.versions.electron` is `40.0.0`, the first Electron release on Node.js 24 |
| Preload scripts | `preload` in `package.json` runs a module in each bundled page's isolated preload context. Page imports of that file receive its exports through the context bridge. A page can also declare `<script type="preload">`, inline or with `src`. There is no `webPreferences.preload`. Preloads run only in pages that ship with the app: bundled `apps:///` pages and files in the app folder. HTML strings from `load()` and other files get no preload. In the preload, `document` is a proxy for the page DOM: values are copied, page objects are handles, and functions can't be passed to the page this way. Like Electron's, a preload gets only `contextBridge`, `ipcRenderer`, `webUtils`, `webFrame`, `nativeImage`, `clipboard` and `shell` of the Electron modules, and main process modules like `app`, `BrowserWindow`, `dialog` and `Menu` are `undefined` |
| `loadFile()`, `load()` | A relative path is relative to `app.getAppPath()`. In main, `loadFile('<name>.html')` with a string literal is bundled like `import.meta.resolve()`, so its scripts, stylesheets and preload work in dev and built apps. Other paths load the file as it is, without its `src` scripts and linked stylesheets. Both return a Promise. A failed load rejects with `ERR_FILE_NOT_FOUND` or `ERR_FAILED` and emits `did-fail-load` |
| Threads | On macOS the main script runs on the main thread and each `BrowserWindow` on its own render thread, with its own JavaScriptCore VM, heap and event loop. A busy main script or window stops no frames in other windows, and a busy page stops no menus, window drags or window calls. They are threads, not OS processes, so a crash in native code ends the whole app. Pages share no globals, as in Electron, but they share web storage. A key that a busy page doesn't answer within 100 ms also goes to AppKit, so a menu shortcut can fire. `before-input-event` runs on the main thread before the page gets the key. As in Electron, `preventDefault()` doesn't stop an input method that composes text. While a main script waits in a nested loop, like `dialog.showMessageBoxSync()`, the event doesn't fire and keys go to the page. `close()` and quitting don't wait for a running page script, and stop it within about 100 ms. Native addons and `node:ffi` calls in preload scripts run on the render thread, so they can't use AppKit. On Windows and Linux everything shares the main thread |
| IPC | Values follow structured clone. Functions, symbols and promises throw `An object could not be cloned.`, but `contextBridge` values can hold them. Listeners run in a later task of the receiver, in send order. Exceptions in `ipcMain` listeners, and in `closed`, `destroyed` and `window-close` listeners, go to `uncaughtException`, or to the console |
| `BrowserWindow` `webContents` | `print()` is not supported, and `debugger` is only for guests. `session` is the default session. `executeJavaScript()` works, while page code still can't run strings. Zoom is per window, not per origin, and `zoom-changed` is not emitted. `setWindowOpenHandler()` opens only bundled pages and local files, so other URLs are denied: open them with `shell.openExternal()` in the handler. `window.open()` returns `null` or an object with only `closed` and `close()` |
| `WebContentsView` | Uses the system WebKit (WKWebView, WebView2 or WebKitGTK), so `did-fail-load` codes are the platform's, for example `NSURLError` codes on macOS. `will-navigate` can be cancelled on macOS only, and `will-redirect`, `before-input-event`, `context-menu` and `audio-state-changed` are not emitted. There is no Chrome DevTools Protocol, so tools like Playwright can't connect. `debugger.sendCommand()` answers only `Runtime.evaluate`, `Page.captureScreenshot`, `Page.reload`, `Target.getTargetInfo` and `Emulation.setEmulatedMedia`, accepts the `enable` commands, and rejects others. With `setWindowOpenHandler()`, `allow` opens the page in a separate browser window and ignores `overrideBrowserWindowOptions`. `webPreferences` takes `partition`, `javascript`, `devTools` and the safe default values of `nodeIntegration`, `contextIsolation`, `sandbox` and `webSecurity`. Other keys throw an error. On macOS, `executeJavaScript()` on a page whose CSP blocks `eval` runs in an isolated world, which can't see page globals. On Windows and Linux it fails on such pages. `loadFile()` can't load bundled pages. A page's `window.apps.postMessage(data)` arrives as `ipc-message` with the channel `message` |
| `Menu` | Every role has Electron's label and accelerator. `reload` and `forceReload` reload the focused window, and `resetZoom`, `zoomIn` and `zoomOut` zoom it. `shareMenu` is a normal item that does nothing. The default menu has no zoom items. Changes to a `MenuItem` after `setApplicationMenu()` need another `setApplicationMenu()`. Menu icons take file paths. Sublabels require macOS 14.4 or later. `popup()` takes `x`, `y`, `positioningItem` and `callback`, and shows the menu in the focused window. Media key accelerators are not shown in menus, and `globalShortcut.register()` returns `false` for them |
| `Tray` | The constructor, `setImage()` and `setPressedImage()` take file paths. Use an empty string for a title-only tray. Titles support plain text and font options. Call `setContextMenu()` again after editing menu items. Popup menus open at the tray icon |
| `shell`, `clipboard` | `openExternal()` opens only `http`, `https`, `mailto` and `tel` URLs. The clipboard reads and writes text, HTML, RTF, PNG images, and raw pasteboard types with `readBuffer()` and `writeBuffer()`. `readImage()` also reads TIFF. `has()` takes a MIME type or a pasteboard type like `public.png`. Bookmarks and the `selection` clipboard are not supported |
| `Notification` | Needs an app bundle identifier, so in `apps run` `show()` emits `failed` |
| `systemPreferences` | `subscribeNotification()`, `postNotification()` and their local and workspace forms are not supported. `askForMediaAccess()` needs `NSCameraUsageDescription` or `NSMicrophoneUsageDescription` in the app's Info.plist, which `apps build` doesn't add, and rejects without it |
| `net` | `request()` follows redirects, or fails on them with `redirect: 'error'`. `redirect: 'manual'`, the `redirect` and `login` events and the `session`, `partition`, `credentials` and `useSessionCookies` options are not supported. `resolveHost()` uses the system resolver and takes only `queryType`. `isOnline()` checks for a network interface with a routable address and is always `true` on Windows |
| `webUtils` | `getPathForFile()` knows only files dropped on a page |
| `open-url` | The URL scheme must be in the app's `Info.plist`, which `apps build` doesn't add. `setAsDefaultProtocolClient()` works only in a built app |
| `relaunch()` | Works in built apps. `apps run` ignores it |
| `setPath()`, `setName()` | Change only the values that `app` returns. Web storage keeps its own location |
| `commandLine` | Switches can be added and read, but they don't change apps. `disableHardwareAcceleration()` does nothing, because apps always draws on the GPU |
| Login items | Need macOS 13 and a built app. Only `openAtLogin` and `status` are returned |
| Images | `dock.setIcon()` and `iconPath` take a file path. `nativeImage` decodes, resizes, crops and encodes images, and has no scale factors or named images. `app.getFileIcon()` returns an icon on macOS only |
| `BrowserWindow` options | `webPreferences` and options that only tune Chromium, like `thickFrame` and `paintWhenInitiallyHidden`, are ignored. The others are `width`, `height`, `x`, `y`, `useContentSize`, `center`, `minWidth`, `minHeight`, `maxWidth`, `maxHeight`, `resizable`, `movable`, `minimizable`, `maximizable`, `closable`, `focusable`, `alwaysOnTop`, `fullscreen`, `skipTaskbar`, `show`, `parent`, `modal`, `title`, `icon`, `backgroundColor`, `hasShadow`, `opacity`, `frame`, `transparent`, `titleBarStyle`, `trafficLightPosition`, `vibrancy` and `visualEffectState`. Unknown options throw an error. `titleBarStyle` is `default`, `hidden` or `hiddenInset`. As in Electron on macOS, `skipTaskbar` and `icon` do nothing there. `setVibrancy()` ignores `animationDuration` |
| `BrowserWindow` state | Getters return cached values. A setter changes them at once, and the real values arrive with the window events. For example, `getPosition()` is correct after `center()` once `move` fires. `resized` also fires after `setSize()` and `maximize()` |
| Frameless windows | On Linux, `frame: false` and a hidden title bar remove the window border, so the window can't be resized from its edges |
| `will-resize`, `will-move` | Fire for resizes and moves by the user on macOS, not while a main script waits in a nested loop. `details.edge` is `right` or `bottom`, and `preventDefault()` doesn't stop a move, both as in Electron on macOS |
| Recent documents | `app.addRecentDocument()` needs the file type in the app's `Info.plist`, which `apps build` doesn't add |
| `BrowserWindow` on Windows and Linux | Sizes and bounds are the content area. `setPosition()`, `center()`, `hide()`, `showInactive()`, `moveTop()`, `blur()`, `unmaximize()`, the size limit setters, `setResizable()`, `setMovable()`, `setMinimizable()`, `setMaximizable()`, `setClosable()`, `setAlwaysOnTop()`, `setHasShadow()`, `setIgnoreMouseEvents()`, `setFocusable()`, `setAspectRatio()`, `setProgressBar()`, `flashFrame()`, `setSkipTaskbar()`, `setIcon()`, `setMenu()` and `removeMenu()` throw an error, as do `setOpacity()` on Windows and `setVisibleOnAllWorkspaces()` on Linux. The `opacity`, `hasShadow`, `focusable`, `skipTaskbar`, `icon` and `vibrancy` options are ignored, and on Linux also the size limit, `maximizable`, `closable` and `alwaysOnTop` options. Modal windows don't block their parent, and on Wayland `parent` has no effect. As in Electron, `setVibrancy()` does nothing there, and neither do `setOpacity()` and `setContentProtection()` on Linux. `isMinimized()` is always `false`, and `restore()` focuses the window |
| `getAppMetrics()` | Returns one entry for the whole app, with its memory only. The CPU values are 0 |
| Not supported | Jump lists, user activities, `setAppLogsPath()`, GPU info, proxy, certificates and accessibility APIs. In `BrowserWindow`: `setKiosk()` |

## Node Integration

The main process, preload scripts and their workers can import these built-in modules, with or without the `node:` prefix: `assert`, `async_hooks`, `buffer`, `child_process`, `crypto`, `diagnostics_channel`, `dns`, `events`, `fs`, `http`, `https`, `module`, `net`, `os`, `path`, `perf_hooks`, `process`, `querystring`, `readline`, `stream`, `string_decoder`, `timers`, `tls`, `tty`, `url`, `util`, `v8`, `worker_threads` and `zlib`. `undici`, `ws` and `node-pty` are also built in for the main process. Imports of these names never load a package from `node_modules`. Their `/promises`, `/strict`, `/posix`, `/win32`, `/types`, `/consumers` and `/web` subpaths also work. `node:sqlite`, `node:ffi` and `node:sea` are available too.

`@pierre/apps` follows the Node.js 24 API, so `process.version` is `v24.0.0`. Deprecated and experimental APIs are not included. These parts differ from Node.js:

| Feature | Support |
|---|---|
| Other modules | `cluster`, `dgram`, `domain`, `http2`, `inspector`, `punycode`, `repl`, `test`, `trace_events`, `vm` and `wasi` are not supported. Importing them fails at build time. A `require()` of them, or of any module that can't be found, throws `MODULE_NOT_FOUND` when it runs. `constants` and `sys` work, but `constants` has no named imports |
| `ns.fn()` | In built apps, a function called through `import * as ns` gets `this` as `undefined`, like other bundlers, where the standard says `ns`. `apps run` follows the standard |
| Import attributes | `with { type: 'text' }` imports a file as a string. For an HTML file in the main process, the string is the bundled page. A `.json` file is a JSON module with or without `type: 'json'`. Other types are ignored. `import()` takes its type only from an object literal, like `{ with: { type: 'text' } }` |
| `require()` | App code is ESM. CommonJS works in `node_modules`, with `module`, `__filename` and `__dirname`. `require()` with a computed name and `module.createRequire()` load built-in modules only. `require.resolve()` finds string literals only. `require.main` is `undefined`, because the entry is ESM. `require()` uses the package `main`; `import` uses `main`, then `module` |
| `import.meta.url`, `__filename` | In built apps they point into the app: `import.meta.url` is `apps:///` plus the path in the app, and `__filename` is that path in the app folder. `url.fileURLToPath()` turns the URL into the same path. `import.meta.filename` and `import.meta.dirname` work in main, preload scripts and workers; pages get `undefined`. Files outside the app folder, like packages in a parent `node_modules`, keep their path relative to it, like `apps:///../shared/x.js` |
| Partial modules | `AsyncLocalStorage` keeps its store only in the synchronous part of `run()` and in functions from `bind()` and `snapshot()`, not across `await`. `tls` has client sockets only: `tls.createServer()` and client certificates (`cert`, `key`, `pfx`) throw. `tls.connect()` also takes a connected `socket`, for STARTTLS. `ca` replaces the system roots for the connection, as in Node. `checkServerIdentity`, `minVersion`, `maxVersion`, `ciphers` and sessions are not supported, `getPeerCertificate()` returns only `raw`, and `rootCertificates` and `getCACertificates()` are empty. `v8` reports process memory as heap statistics, its `serialize()` uses JSON, and it has no heap snapshots. `undici` wraps `fetch`, so `dispatch()` and `Agent` connections don't work |
| `ELECTRON_RUN_AS_NODE` | With this variable the executable runs a script headless, with no windows, and it can run a script chunk from `import.meta.resolve('./file.ts')`. With `NODE_CHANNEL_FD` it talks to its parent like a forked Node.js process. `--require` is ignored |
| `process` | `memoryUsage()` returns `rss` only, the heap values are 0. An unhandled promise rejection is logged and does not stop the app. An error given to `reportError()` fires `error` on `globalThis` and then goes to `uncaughtException`, or to the console. `process.kill()` doesn't work on Windows. A built app gets all of its arguments in `process.argv` after the executable, like Electron, so there is no script path. `process.exit()` throws in preload scripts |
| Timers | The main process runs until it quits, so `ref()` and `unref()` have no effect there. In `worker_threads` workers, `unref()` lets the worker end while the timer is pending |
| `perf_hooks` | `performance` records marks, measures and `timerify()` entries only, with no resource timing. In the main process on Windows and Linux, `eventLoopUtilization()` counts time spent drawing windows as idle |
| `worker_threads` | Workers get the environment of the app process, not the parent's `process.env`, so `SHARE_ENV` and the `env` option have no effect. The `argv`, `execArgv`, `stdin`, `stdout`, `stderr` and `resourceLimits` options are ignored. A `BroadcastChannel` in a page only reaches channels of the same page |
| `fs` | File descriptors are `@pierre/apps` handles, not OS descriptors, except the ones a process inherited. `statfs()` doesn't work on Windows. `glob()` takes `*`, `?`, `[...]`, `{a,b}` and `**`, without extglobs or `{1..3}` ranges, and `fs.promises.glob()` yields its matches after the walk ends. `openAsBlob()` reads the whole file into memory. `readableWebStream()` of a FileHandle returns a default stream, not a byte stream |
| `child_process` | `fork()` starts the app's executable with `ELECTRON_RUN_AS_NODE`. It runs a script that the build can find, like `import.meta.resolve('./child.ts')` or `path.join(__dirname, 'child.ts')`, or any file with `execPath: 'node'`. IPC uses Node's `json` serialization, so a real Node.js parent or child can be on the other side. `serialization: 'advanced'` and sending sockets or servers throw, and so does `'ipc'` on Windows. Other `stdio` entries past 2 are `'pipe'` socket pairs. The `uid` and `gid` options throw on Windows. The child's `stdout` and `stderr` are readable streams, not sockets |
| `crypto` | Hashes are `md5`, `sha1`, `sha224`, `sha256`, `sha384` and `sha512`. HMAC, `pbkdf2()` and `hkdf()` support all of them. Ciphers are `aes-128-gcm`, `aes-256-gcm` and `chacha20-poly1305` with a 12-byte IV, and a cipher keeps the message in memory until `final()`. A decipher takes only a 16-byte authentication tag. Keys are RSA, EC P-256 and P-384, and Ed25519. Encrypted keys, compressed EC points and EC private keys without their public key can't be read, and keys are not exported encrypted. P-256 keys sign with SHA-256 and P-384 keys with SHA-384. RSA keys sign with 2048 to 4096 bits, and RSA-PSS salts are as long as the digest. `generateKeyPair()` makes `ec` and `ed25519` keys only. There is no Diffie-Hellman, ECDH, `X509Certificate`, `KeyObject.from()`, `publicEncrypt()` or `argon2()`. `crypto.subtle` has SHA digests, HMAC, AES-GCM, PBKDF2, HKDF, Ed25519, ECDSA (P-256 with SHA-256, P-384 with SHA-384), RSASSA-PKCS1-v1_5 and RSA-PSS, with `raw`, `jwk`, `spki` and `pkcs8` keys. `wrapKey()` and `unwrapKey()` wrap with AES-GCM keys only. It can't generate RSA keys, and it has no AES-CBC, AES-CTR, AES-KW, RSA-OAEP, ECDH or X25519. A private key is checked when it signs, not when it is imported, and `deriveBits()` runs on the calling thread |
| `zlib` | Gzip, deflate and raw deflate only, there is no Brotli or Zstd. `params()` keeps the old level when the new one needs a different strategy. Streams compress on the JavaScript thread |
| `os` | `cpus()` times are 0. On Windows, `networkInterfaces()` returns `{}`, `loadavg()` returns zeros, `version()` returns `Windows`, and `getPriority()` and `setPriority()` throw |
| `dns` | `resolve*()`, `reverse()`, `lookupService()` and `Resolver` use the system resolver library and don't work on Windows. `setServers()` takes IPv4 servers only, timeouts are rounded up to seconds, and `Resolver` has no `setLocalAddress()` |
| `http`, `https` | `request()` uses `fetch`. It sends the body when `end()` is called, follows redirects, decodes gzip responses (without their `content-encoding` header) and reports the standard status text. `Agent` exists, but requests don't use its sockets. Servers listen on TCP ports only, by default on `0.0.0.0`. `https.createServer()` throws, because `@pierre/apps` has no TLS server. `https.request()` checks certificates against the system roots. `rejectUnauthorized`, `ca`, `cert` and `key` are ignored, so servers with self-signed certificates fail |
| `net` | The default host is IPv4. `'lookup'` fires only when a connection succeeds, with the address that answered, and there is no automatic family selection |
| `node:sqlite` | No extensions, limits or `Session` |
| Node-API | Addons get version 8. `napi_get_uv_event_loop()` fails, because there is no libuv loop |
| `readline` | Reads lines from streams. There is no terminal line editing, history or completion |
| `util.inspect()` | The state of a Promise, the items of a Map or Set iterator and Proxy details are not shown |
| `util.types` | `isExternal()` always returns `false`, and `isProxy()` returns `false` for a revoked Proxy |
| `buffer` | `kMaxLength` is 2^32 - 1, the JavaScriptCore limit. `transcode()` converts between `ascii`, `latin1`, `utf16le` and `utf8` |
| `tty` | There is no stdin, so `tty.ReadStream` throws. `tty.WriteStream` works for descriptors 1 and 2 when they are terminals. On Windows, `columns` and `rows` are always 80 and 24, and `resize` is not emitted |
